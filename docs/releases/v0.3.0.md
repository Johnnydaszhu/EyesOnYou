## EyesOnYou 0.3.0

### Know how your proxy is actually set up

Proxy apps hook into macOS in very different ways, and "system proxy is on" was never the whole story. The status chip now names the real arrangement:

- **VPN Proxy Active** — the proxy settings come from a VPN (NetworkExtension) and outrank anything in Network Settings. This is what Shadowrocket and Clash enhanced mode do.
- **VPN Tunnel (TUN)** — a tunnel is capturing everything at the IP layer with no system proxy set at all.
- **PAC Proxy** — routing is decided per-URL by a script.
- **System Proxy On / Off** — the classic settings-layer case.

Hovering explains what each means, shows the endpoint, and flags fake-IP DNS (domains being resolved inside the tunnel).

### Say so when a VPN is hiding per-app routing

Previously, turning on per-app routing while Shadowrocket was connected reported success while no traffic ever reached EyesOnYou — the VPN's proxy settings quietly won. That case is now detected and named: the badge reads **App Rules Shadowed** and explains that the VPN app's settings take priority while its tunnel is up.

Routing is not torn down when this happens. The moment the VPN disconnects, per-app rules take effect on their own.

### Measured routes when you run Clash

If a Clash or mihomo controller is reachable, EyesOnYou reads its live connection list and uses it as route evidence: which app went through a node, which went direct — measured per connection rather than inferred. Apps with mixed evidence stay undecided instead of being rounded to whichever side is larger. Shadowrocket exposes no equivalent interface, so nothing changes there.

### Force Direct now really is direct

Under a TUN-mode proxy, a "direct" connection used to be pulled straight back into the tunnel. Direct dials are now bound to the physical interface, so the rule does what it says.

### Also in this release

- Per-app routing chains correctly to a VPN-provided proxy that `networksetup` never showed.
- SOCKS system proxies no longer block per-app routing from starting.
- Failure states explain the cause and offer the matching fix, instead of a bare error string.
- CLI: `eyesonyou clash` reports measured per-process routes; `eyesonyou enforce status` reports the deployment mode and whether a takeover is being shadowed.

### About "precise mode"

This build contains a NetworkExtension transparent proxy that enforces per-app rules at the socket layer — it works for apps that ignore proxy settings and cannot be shadowed by a VPN tunnel.

**It cannot run in this download.** Loading a system extension requires a signature carrying Apple's Network Extension entitlement, which is not present in an ad-hoc build. Turning the switch on reports exactly that rather than failing silently. It is included so the code ships with the release it belongs to; a signed build will follow.

### Install

1. Download `EyesOnYou-0.3.0.dmg`.
2. Open the disk image and drag **EyesOnYou** into **Applications**.
3. Launch EyesOnYou from Applications and keep it running while you want traffic measured.

Per-app routing covers HTTP and HTTPS connections from apps that follow the macOS system proxy. Raw TCP, UDP, QUIC, and proxy-unaware apps need the signed Network Extension described above.

The GitHub download is ad-hoc signed and is not notarized.
